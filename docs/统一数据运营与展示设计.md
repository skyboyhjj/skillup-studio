### 1.2 差距分析

| # | 差距 | 现状 | 影响 |
|---|------|------|------|
| 1 | **采集串行、手动** | 四源各自独立跑，无并行/重试/超时 | 全量采集耗时长；单源失败需人工重跑 |
| 2 | **无状态机** | 无 pending/running/success/failed 追踪 | 失败不可审计，断点不可恢复 |
| 3 | **质量检测分散** | validator 在管线末尾，无独立质量视图 | 截断（HF MAX_PAGES）、空月（BAAI 08）问题事后才发现 |
| 4 | **展示分散** | 论文页/仪表盘/追踪引擎（即将上线）各自为政 | 用户需跨页面拼装全貌 |
| 5 | **版本靠人工纪律** | canonical/树文件/诊断/版本号四同步手动执行 | 标注三次分裂教训——需要机制化 |
| 6 | **无采集日志/监控** | 无采集时间/量级/耗时/错误记录 | 无法追溯"这月数据怎么了" |

## 二、统一数据运营设计

### 2.1 管线调度：四源并行采集

**目标**: 一键触发、四源并行、源级容错、断点续跑、可审计。

```
┌─────────────────────────────────────────────────────────┐
│  pipeline_orchestrator.py（调度器，monthly_pipeline 采集段增强） │
│                                                         │
│  [调度] 采集 → 质量门 → 诊断 → 合并 → 验证 → 展示打包            │
│           │                                              │
│           ▼ 四源并行（ThreadPoolExecutor, max_workers=4）  │
│   ┌───────┬───────┬───────┬───────┐                       │
│   │ arXiv │ BAAI  │ GitHub│  HF   │  ← 各源独立 try/except │
│   └───────┴───────┴───────┴───────┘                       │
│   单源失败 → 标记 failed，不阻断其他源（源级容错）              │
│   失败源可单独重跑（--source arxiv --month 2026-08）         │
└─────────────────────────────────────────────────────────┘
```

**调度器规格**:

| 项 | 设计 |
|----|------|
| 并行 | `ThreadPoolExecutor(max_workers=4)`（网络 IO 密集，线程足够） |
| 重试 | 网络错误指数退避 3 次（1s/2s/4s），HTTP 5xx 重试、4xx 不重试 |
| 超时 | 每源硬超时 15 分钟（requests timeout=60s × 自动切片） |
| 幂等 | 按月快照：同月存在且校验通过 → 跳过（`--force` 覆盖） |
| 增量 | 论文级采集支持 `--since` 增量（arXiv API 按 updated 过滤） |
| 状态机 | 每源 × 每月: `pending → running → success / failed(原因)` |
| 断点续跑 | 失败源记录于 run 日志，重跑只处理 failed 源 |
| 触发 | ①手动 `python pipeline_orchestrator.py` ②定时（月初 cron）③补采 `--month` |

**运行日志**（沉淀为可审计记录）:

```json
{
  "run_id": "2026-08-01T03:00:00Z",
  "trigger": "cron",
  "sources": {
    "arxiv": {"status": "success", "n_nodes": 13364, "elapsed_s": 312, "errors": []},
    "baai":  {"status": "success", "n_nodes": 403, "elapsed_s": 58, "errors": []},
    "github": {"status": "failed", "n_nodes": 0, "elapsed_s": 240, "errors": ["rate_limit: 403"]},
    "huggingface": {"status": "success", "n_nodes": 25091, "elapsed_s": 480, "errors": [], "warnings": ["MAX_PAGES=20 触底，可能截断"]}
  }
}
```

### 2.2 质量门（数据治理）

**目标**: 数据进入诊断前必须过门；异常自动标记，不静默污染后续环节。

**校验检查点（data_validator 五检查点扩展 → 七检查点）**:

| # | 检查点 | 规则 | 对应教训 |
|---|--------|------|----------|
| 1 | schema 完整性 | 节点必有 id/name/weight；树必有 schema_version/source/month | 统一 schema |
| 2 | 五行合法 | wuxing ∈ {木火土金水}，非法值拒绝 | default bug（"llm" 误作五行） |
| 3 | 权重为正 | weight > 0，0 或负告警 | 空月 n_nodes=0 |
| 4 | 量级合理性 | 与近 3 月均值偏差 > 3x 告警（不阻断，标记 warning） | HF text-to-image -79% 截断嫌疑 |
| 5 | 空月检测 | n_nodes=0 → 告警 + 触发回退策略（EngineAdapterV2 已有） | BAAI 08 空月 |
| 6 | 截断检测 | 采集页数触 MAX_PAGES 底 → warning | HF MAX_PAGES=20 |
| 7 | 标注一致性 | canonical ↔ 树文件 ↔ 诊断输出 ↔ 版本号 四者 diff 为零 | 标注三次分裂 |

**质量报告**（每次运行生成 `output/reports/quality_YYYY-MM.json`）:

```json
{
  "month": "2026-08",
  "checks": {"arxiv": {"schema": "pass", "wuxing": "pass", "volume": "pass",
                        "empty": "pass", "truncation": "pass", "annotation": "pass"},
              "baai": {"empty": "FAIL(n=0)", "fallback": "auto_rollback_05/06/07"}},
  "annotations_ok": true,
  "verdict": "baai 空月已回退，其余通过——可进入诊断"
}
```

### 2.3 版本与元数据

**schema_version 升级 v1.0 → v1.1**（树文件头加 metadata）:

```json
{
  "schema_version": "1.1",
  "source": "arxiv",
  "month": "2026-08",
  "metadata": {
    "collector": "arxiv_ai_collect.py v1.2",
    "collected_at": "2026-08-01T03:12:00Z",
    "annotation_version": "v2",
    "coeff_version": "v1.1_calibrated",
    "engine": "wuxing_diagnose_v2",
    "quality_gate": "pass"
  },
  "nodes": [...]
}
```

**版本链**（四层联动，任一变更需同步）:

```
采集版本（collector vX）→ 标注版本（annotation vX）→ 系数版本（coeff vX）→ 引擎版本（engine vX）
  每层变更 → 重跑质量门 → merged_series.json 打版本戳 → 报告注明口径
```

**口径记录**: merged_series.json 已有 `engine`/`generated` 字段，升级为完整 `provenance` 块（采集/标注/系数/引擎版本全链）。

### 2.4 监控与告警

**监控面板数据**（供前端展示 + 运维告警）:

| 指标 | 计算 | 告警阈值 |
|------|------|----------|
| 采集成功率 | success 源数 / 总源数 | < 75% 告警 |
| 数据量级 | n_nodes 与历史均值比 | > 3x 或 < 0.3x |
| 截断率 | 触 MAX_PAGES 采集数 / 总采集数 | > 0 |
| 空月数 | n_nodes=0 源×月数 | > 0 |
| 标注漂移 | 四同步 diff 数 | > 0 |
| 管线耗时 | 采集→展示全链路 | > 60 min 提示 |

## 五、与既有体系的关系

| 既有模块 | 在统一体系中的角色 |
|----------|-------------------|
| monthly_pipeline.py | 调度器接管采集段，诊断/合并/验证段保留原编排 |
| engine_adapter_v2.py | 诊断段核心（时间演化 + 空月回退），不变 |
| data_validator.py | 扩展为七检查点质量门，前置到调度链 |
| papers.html / 论文采集器 | 展示层"论文列表"区复用其卡片/筛选/导出交互 |
| 产品矩阵 Design Token | 全站视觉基准 |
| 五行诊断仪表盘 | 图表配色与手绘方案沿用 |

*设计原则：运营层（调度/质量/版本）机制化，展示层（交互/视觉）复用既有资产——不重复造轮子，只补齐缺口。*
