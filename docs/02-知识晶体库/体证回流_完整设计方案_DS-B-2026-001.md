## 一、背景与目标

### 1.1 现状

S3 已交付 TizhengCard 生成器（`build_tizheng_card.py`），卡片以 `status: draft` 生成，正文含"体证记录（证）"三问占位（我做到了什么 + 我的体验是什么 + 验证/颠覆了哪个认知），但：

- 无"用户填写体证 → 状态流转"的机制
- 无"体证进入公共智慧池"的通道（SOP Step 7"可选择性上传至社区（匿名）"未落地）
- 无跨边界信任护栏

### 1.2 目标

1. **个人闭环**：用户填写"证"三问 → 卡片 `draft → completed`（用户亲证即验证，不加外部审核）
2. **公共智慧池**：completed 卡片**可选**匿名化入池 → 聚合体证洞察 → 反哺检索
3. **信任边界**：个人→公共边界设三道轻量护栏（机器合规检查 + 用户确认 + 信任标记），**不引入审核员实体**

### 1.3 非目标（奥卡姆）

- ❌ 不新增人工审核流程（无审核员角色）
- ❌ 不强制上传（上传始终可选，SOP Step 7）
- ❌ 不引入新数据库（公共智慧池 = 晶体库内新增 `wisdom/` 目录 + 索引，沿用 OKF 契约）

## 二、总体设计

### 2.1 数据流总览

```
① 生成（S3 已有）              ② 践行 + 填写（新增）          ③ 回流（新增，可选）
┌──────────────┐   draft   ┌────────────────────┐  completed  ┌─────────────────────┐
│ build_tizheng │ ────────► │ 用户践行 + 填"证"三问 │ ──────────► │ 公共智慧池（匿名）    │
│ _card.py      │  Tizheng  │                    │             │ wisdom/ + 索引       │
└──────────────┘  Card     └────────────────────┘             └─────────────────────┘
                                │                                  ▲
                                │ 边界①（不加审核）                 │ 边界②（三道护栏）
                                ▼                                  │
                          completed 卡片                   机器检查 + 用户确认 + 信任标记
                          （留在 tizheng/）
```

### 2.2 状态机

```
draft ──(填"证"三问 + 确认)──► completed ──(可选 + 匿名化 + 确认)──► published（入池）
  │                               │
  └──(废弃：不践行)──► retired    └──(撤回)──► draft（可重填）

状态语义（对齐晶体契约 IF-2026-006）：
  draft      生成待践行
  completed  用户亲证完成（体证三问已填）
  published  匿名化入公共智慧池（仅池中副本；原卡片保持 completed）
  retired    用户放弃践行（显式标记，KSMG G3）
```

**关键点**：`published` 是池中**副本**的状态，原卡片 `status` 保持 `completed`（引用不复制——原卡片引用池条目，池条目引用原卡片，双向 ref）。

## 三、边界①：个人闭环（draft → completed）

### 3.1 设计决策

**不加外部审核、不加"再验证"**（用户确认采纳）。理由：

- 体证是**第一人称体验**——审核自己的体验在逻辑上不成立
- S3 定案 `verified: human:hjj`（human-reviewed 层）已是最高信任层级
- 与诊断晶体的 `process:quality-gate`（机器确认）形成双层，职责已分

### 3.2 完成条件（机器校验，非审核）

用户提交"证"三问时，生成器做**格式自检**（防空/防占位，不算审核）：

| 检查 | 规则 | 失败处理 |
|------|------|----------|
| 三问完整 | 做到了/体验/认知验证 三问均非空 | 提示补全，不流转 |
| 非占位 | 不含"（用户践行后填写"等模板残留 | 提示重写 |
| 长度下限 | 每问 ≥ 10 字（防敷衍） | 提示补充 |

自检通过 → `status: draft → completed`，frontmatter 追加：

```yaml
x-evidence:                    # 新增：体证证据块
  completed_at: 2026-08-15T21:30:00Z
  done: 我做到了什么……          # 三问原文（个人文件，不匿名）
  experience: 我的体验是什么……
  cognition_shift: 验证/颠覆了哪个认知……
  word_count: { done: 42, experience: 58, cognition_shift: 35 }
```

### 3.3 命令（个人闭环，脚本 B-1）

```bash
python complete_tizheng.py --card output/crystals/tizheng/tizheng_hjj_20260812_044309.md \
    --done "……" --experience "……" --cognition "……"
# 校验通过 → status: completed + x-evidence 写入
```

## 四、边界②：个人→公共（completed → 公共智慧池）

### 4.1 三道护栏（机器自动 + 用户确认，无人工审核员）

```
completed 卡片
  │
  ▼
护栏1 · 匿名化核验（机器）
  ├─ 扫描 x-evidence 与事件文本：姓名/手机/邮箱/公司/地点等 PII 模式
  ├─ 命中 → 标记需脱敏，提示用户修改后重提
  └─ 通过 → 继续
  │
  ▼
护栏2 · 完整度校验（机器）
  ├─ 三问非空 + 长度 ≥ 10（复用边界①自检）
  ├─ 含具体体验（非纯感想：experience 有动词+情境词）
  └─ 通过 → 继续
  │
  ▼
护栏3 · 用户确认（唯一人类环节，用户即审核者）
  ├─ 展示匿名化预览（脱敏后全文）
  ├─ 用户确认上传 → 继续
  └─ 用户取消 → 中止（不入池）
  │
  ▼
入池：生成 wisdom/<id>.md（published 副本）+ 信任标记
```

### 4.2 信任标记（防"一人之言"冒充"普遍真理"）

池中每条目 frontmatter 强制携带：

```yaml
type: WisdomInsight            # 池内新类型（晶体契约扩展，见 §5）
status: published
verified: { by: human:anonymous, at: ... }   # 匿名亲证（非 process！）
x-evidence:
  sample_size: 1               # 该洞察的体证人数（防以偏概全）
  pooled: true                 # 已匿名化入池
  source_ref: tizheng/tizheng_hjj_....md     # 回指原卡片（引用不复制）
```

**检索端语义**（对接 S4 `retrieve_crystals.py`）：`verified: human:anonymous` 的条目在 View 层**永远标注样本量**——检索结果展示 `（体证 1 人）`，不做无保留的普遍性断言。

### 4.3 命令（回流，脚本 B-2）

```bash
python pool_tizheng.py --card output/crystals/tizheng/tizheng_hjj_....md \
    --confirm yes    # 唯一交互：用户确认匿名化预览
# 护栏全过 → output/crystals/wisdom/<id>.md（published）+ 原卡片 x-ref.pooled 回注
```

## 五、公共智慧池数据设计

### 5.1 目录与索引（沿用晶体库 OKF Bundle）

```
output/crystals/
├── wisdom/                     # 新增（KnowledgeDomain 预留的伴生结构）
│   ├── index.md                # 池总览（N 条体证洞察 + 样本量分布）
```

### 5.2 WisdomInsight 条目 schema（对齐 OKF）

```yaml
---
type: WisdomInsight
title: 体证洞察：放下执念后的平静（识位·低）
status: published
generated: { by: pool_tizheng.py/0.1, at: 2026-08-15T22:00:00Z }
verified: { by: human:anonymous, at: 2026-08-15T21:30:00Z }
sources:
  - id: mirror-10-识位轴-低
    resource: daojing_database_v2.json#dimensions
x-mirror:
  chapter: 10
  dimension: 识位轴
  p_level: 低
  classic: 载营魄抱一
x-wuxing:
  weak: 水
  complement: 水
x-evidence:
  sample_size: 1
  pooled: true
  source_ref: tizheng/tizheng_hjj_....md
x-relation:                      # 与 S4 检索打通
  related_classics: [第10章 · 载营魄抱一]
---
正文：匿名化后的体证摘要（三问精炼版，≤200 字）
```

**新增实体审计（奥卡姆）**：
- `WisdomInsight` 类型——**必须**：池中副本需要区别于原卡片的类型语义（published 副本 + 匿名）
- `x-evidence` 块——必须：样本量/匿名标记是信任护栏的载体
- 无新数据库、无新服务——沿用晶体库目录 + 现有脚本

## 六、B-3 回注（经典↔践行双向检索，S4 串联）

completed/published 的体证按镜鉴章回注 ClassicalInsight：

```yaml
# classical_v02/10.md 追加
x-application:                  # 新增：践行反注
  tizheng_count: 1              # 本章关联体证数
  wisdom_refs: [wisdom/w-2026-08-001.md]
```

- 触发时机：体证入池时自动回注（B-2 内联）
- 检索效果：S4 `--kw 载营魄抱一` → 命中经典章 + 相关体证/智慧条目（双向可达）
- **只回注池中（匿名）条目**——个人 completed 卡片不回注（隐私）

## 九、验收标准

- [ ] 边界①：填证三问后卡片 `completed`，frontmatter 含 `x-evidence`（自检拦截空/占位）
- [ ] 边界②：含 PII 卡片被护栏 1 拦截；确认后入池，`verified: human:anonymous`
- [ ] 信任标记：池条目 `sample_size` 正确；S4 检索 WisdomInsight 显示样本量
- [ ] 引用不复制：池条目仅 ref 原卡片，无正文复制（≤200 字精炼摘要例外，属新产出）
- [ ] 隐私：个人 completed 卡片不回注经典章；仅池中匿名条目回注
- [ ] 可复跑：全流程两次执行 diff 仅时间戳/ID

## 十、风险与边界

| 风险 | 缓解 |
|------|------|
| 匿名化不彻底（AI 生成内容仍可指认作者） | 护栏 1 做 PII 模式扫描 + 用户预览确认；**不承诺绝对匿名**，池条款注明"匿名化尽力而为" |
| 体证质量参差（泛泛而谈） | 护栏 2 完整度检查（长度+具体性）；不过关提示补充 |
| 一人之言被当普遍真理 | 样本量标记强制展示（`sample_size: 1` 不隐藏） |
| 撤回困难 | `published → draft` 撤回路径保留（状态机含 retired/撤回） |

---

## 十一、一句话定位

> **体证回流 = 两个边界 + 一个池：个人闭环（draft→completed）不加审核——用户亲证即验证（human 层）；个人→公共（completed→published）设三道轻量护栏——机器合规检查（匿名化/完整度）+ 用户确认（唯一人类环节）+ 信任标记（样本量永远可见）。不引入审核员实体，公共智慧池是晶体库的 wisdom/ 目录而非新系统。体证从"个人修行记录"升级为"可被检索、可反哺经典、样本量透明的公共智慧"——个人地图向安人地图的通道正式开通。**

*待审核要点: ① WisdomInsight 类型是否可接受（唯一新增实体）② 三道护栏的强度是否合适 ③ 匿名化"尽力而为"承诺的边界 ④ 样本量强制展示是否足够防以偏概全*
