## 二、核心概念：知识晶体（OKF × 五行 × 可计算）

**定义**：知识晶体 = 最小独立的知识单元，具备三重属性：

```
┌──────────────────────────────────────────┐
│            知识晶体（Crystal）             │
│                                          │
│  ① OKF 结构层：type/status/sources/      │
│     generated/verified（谁产生、谁验证、   │
│     是否仍有效）                          │
│  ② 五行语义层：x-wuxing（归属/主导/阶段/   │
│     生克关系）——可参与五行诊断计算         │
│  ③ 可计算层：带权重/边/可组合（参与        │
│     S_p、C_k、演化路径等计算）            │
└──────────────────────────────────────────┘
```

**与附件"矛盾迭代"的呼应**：
- 旧矛盾：混沌文档（矢量）→ 存储更多（为学日益）
- 新矛盾：知识晶体（旋量）→ 结晶更纯、连接更活（为道日损）
- **晶体库不是"更精密的语料库"，而是"活的觉知网络"**——OKF 是名（手指），晶体化是通往月亮的路。

## 三、晶体 Schema（对齐 OKF v0.2 + x-wuxing 扩展）

```yaml
---
# OKF 结构层
type: KnowledgeDomain | DiagnosisResult | ClassicalInsight | TizhengCard
title: 计算机视觉领域月度画像
description: CV 领域 2026-08 月度知识树节点诊断
generated: { by: pipeline_orchestrator/0.2, at: 2026-08-10T09:00:00Z }
verified: { by: process:quality-gate, at: 2026-08-10T09:01:00Z }   # 或 human:<id>
sources:
  - id: arxiv-2026-08
    resource: arxiv_tree_2026-08.json
    usage_count: 2519
status: current                                    # draft/current/deprecated/retired

# 五行语义层（x-wuxing 扩展）
x-wuxing:
  dominant: 水
  sp: 39.4
  stage: 克
  shell_sp: 7.48
  nucleus_sp: 8.45
  evolution: 木→水→水

# 可计算层（引用计算层 JSON，不复制）
x-compute:
  ref: engine_v2_series.json#arxiv
  c_k: 0.0
  k_y: 0.2079
---
正文（Markdown）：人机共读的晶体内容
```

**设计要点**：
1. **晶体是"视图"不是"复制"**——`x-compute.ref` 引用计算层 JSON（engine_v2_series.json），晶体只做结构化封装，**不复制数据**（奥卡姆：不建双份）
2. **verified 分两级**：`process:quality-gate`（机器确认）+ `human:<id>`（人工复核——标注仲裁/体证卡片的用户确认）
3. **status 生命周期**：draft → current → deprecated → retired——知识过时显式标记（KSMG G3）

## 四、三层落地

### Base 层：从"文件库"到"知识晶体库"

**附件主张**: Base 层不再是文件库，而是知识晶体库（活的网络）。

**落地方案（奥卡姆：不推翻，加视图）**：

| 现有 Base 内容 | 晶体化方式 | 新增实体？ |
|----------------|-----------|:----------:|
| 道德经 81 章（原文/注释/五步读解） | 每章封装为 `ClassicalInsight` 晶体（type/status/sources/verified） | ❌（已有内容加格式） |
| 概念网络与知识图谱 | 每个概念节点封装为 `KnowledgeDomain` 晶体 + x-wuxing | ❌（已有图谱加格式） |
| 四源诊断结果（engine_v2_series） | 诊断输出封装为 `DiagnosisResult` 晶体（引用 JSON） | ❌（已有输出加视图） |
| 多版本对照 | 保留为晶体的 sources 引用（不复制） | ❌ |

**Base 层铁律不变**："只组织，不生产"——晶体库组织已有知识，不创造新知识。

### View 层：为道日损的晶体检索

**附件主张**: View 层精准抽取并组装知识晶体（如医生配药）。

**落地方案**: 晶体化让"为道日损"可计算——

```
用户提问
  → 晶体检索（五行语义 + OKF status + L1-L4 认知深度）
  → 按用户认知分层组装：L1 白话 → L2 精读 → L3 应用 → L4 学术
  → 只呈现"恰好需要的那一瓢"（用户主权不变）
```

- L1-L4 分层 = 晶体的 `x-wuxing.stage` + 认知深度标记的联合检索
- **五行匹配**：用户当前"缺什么"（如土弱需补土）→ View 优先呈现对应五行晶体——"补其不足"的五行版为道日损
- 预设问题系统不变（善行无辙迹）

### SkillUP 层：体证卡片的封装与回流

**附件主张**: 用户每次真诚的践行（"做到"）封装为带验证信息的"体证卡片"，汇入公共智慧池。

**这是三方融合中唯一真正的新实体**（其余都是格式视图）：

```yaml
---
type: TizhengCard                      # 体证卡片
title: 我在"每日一读"中的践行记录
generated: { by: user:<id>@镜鉴, at: 2026-08-10T20:00:00Z }
verified: { by: user:<id>, at: 2026-08-10T20:00:00Z }   # 用户亲证
sources: [ref: 道德经-第27章-要妙]
x-wuxing:
  dominant: 土
  stage: 变
x-relation:
  validates: [ref: 经典解读-27-1]      # 验证了哪个认知晶体
  challenges: [ref: 经典解读-03-2]     # 或颠覆了哪个
status: current
---
正文：我做到了什么 + 我的体验是什么 + 验证/颠覆了哪个认知
```

**回流机制**: 体证卡片进入公共智慧池 → 成为 Base 层新晶体 → 后续 View 层可引用——**"个人地图"的经验转化为"安人地图"的公共智慧**（BVS 既有概念的直接落地）。

## 五、与现有体系的衔接

| 现有体系 | 在晶体库中的角色 | 衔接点 |
|----------|-----------------|--------|
| 四源管线（采集→诊断→合并） | **晶体源管道**——持续产出 DiagnosisResult 晶体 | 树文件/engine_v2_series 已是"准晶体"（带 provenance） |

## 七、奥卡姆审视：必要实体清单

| 实体 | 必要？ | 理由 |
|------|:------:|------|
| 晶体 Schema（OKF + x-wuxing + x-compute） | ✅ | 三方融合的接口——唯一的"接缝" |
| 晶体导出器（export_crystals.py） | ✅ | 统一封装已有内容（≈200 行） |
| **体证卡片机制**（镜鉴→封装→回流） | ✅ | 唯一真正新增的价值闭环（用户践行→公共智慧） |
| 晶体检索（View 层 L1-L4 × 五行） | ✅ | 让"为道日损"可计算（可复用人现有 View 机制） |
| 新数据库/向量库 | ❌ | 晶体是文件（Markdown+YAML），不需要 |
| 新运行时/框架 | ❌ | 沿用零依赖 Python + 现有前端 |
| 双份数据 | ❌ | 晶体引用计算层 JSON（x-compute.ref），不复制 |

**结论**：晶体库的实体成本 = 1 个 schema + 1 个导出器 + 1 个体证卡片机制 + 检索增强——**其余全部复用现有资产**。
