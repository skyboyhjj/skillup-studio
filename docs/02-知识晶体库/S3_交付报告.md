## 2. 核心流程（实测验证）

```
输入: 事件 + 四维评分
  ↓
① 最低维度: 识位 3 分（核心关注）
  ↓
② 五行映射: 识位 → 水（dimension_map 定案）
  ↓
③ 镜鉴匹配: 第10章·识位·低（triggers 命中或 fallback）
  ↓
④ 五行补益: 水弱 → 补水 → 推荐水 dominant 章（24 章中前 5）
  ↓
⑤ TizhengCard 输出（OKF frontmatter + 知-行-证正文）
```

### 实测卡片（第 1 条）

```yaml
type: TizhengCard
title: 体证：会议上对下属提案感到不耐烦（识位·低）
status: draft
verified: { by: human:hjj }            # 用户亲证（human 层）
x-mirror:
  chapter: 10                          # 镜鉴关联
  dimension: 识位轴 / p_level: 低
x-scores: { shi: 7, yu: 6, identify: 3, yuan: 5 }
x-wuxing:
  weak: 水                             # 识位→水
  complement: 水                       # 补水
  recommend: [第1章道可道, 第4章道冲, 第6章谷神, 第7章长久, 第8章上善若水]
  weak_chapter_count: 24               # 全书水章 24 个
---
# 知（事件）→ 行（镜鉴反馈：第10章涤除玄鉴 + 今日功课 + 反思）→ 证（体证记录）
```

## 3. 关键设计点

| 设计 | 说明 |
|------|------|
| **human 亲证** | verified: human:<id>（用户践行即验证——human-reviewed 层，契约合法）——修了"user:"非法的问题 |
| **镜鉴匹配** | triggers 含事件关键词优先；无命中 fallback 第 10 章（可配置） |
| **五行补益** | 最低维度→dimension_map→weak 行→推荐该行 dominant 章（经典推荐闭环） |
| **知-行-证** | 正文三环节对齐反馈库 SOP（洞察→行动→反思→体证记录） |
| **契约校验** | TizhengCard 类型合法 + verified 正则 + weak 五行合法——G6 精神 |

---

## 4. 实测插曲（契约价值）

`verified: user:hjj` 被 `VALID_VERIFIED` 正则拦截（只允许 process:/human:）——**修正为 human:hjj**：用户亲证本就属于 human-reviewed 信任层级，`user:` 前缀不符合契约。契约第三次在经典/体证层拦截设计错误。
