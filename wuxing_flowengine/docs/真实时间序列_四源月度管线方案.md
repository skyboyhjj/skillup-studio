# 真实时间序列多源数据方案：四源月度管线

> **版本**：V1.0（2026-08-09）
> **背景**：BAAI 知识树单源在时间与数量上有局限，无法支撑"真实时间序列数据"需求（V1.2 系数校准 / H3 抗摇摆 / 跨域 n≥3）
> **核心主张**：多源扩展 + 官方 API 优先——P0（arXiv+BAAI）+ P1（GitHub+HuggingFace）四源并行，统一 schema，月度快照管线

---

## 一、需求澄清：我们需要的"时间序列"是什么

| 需求 | 数据形态 | 对应验证 |
|------|---------|---------|
| V1.2 系数校准 | 节点树的**月度快照**（领域→子领域节点数演化）→ 五行分布时间序列 → O_t/E_u/C_k/K_y 演化 | v0.1_initial → v1.1_calibrated |
| H3 抗摇摆校准 | 某方向热度波动时，方法种子是否保持 | 纯粹度抗摇摆 |
| 跨域可比性 | **第 3 个域**（目前只有 BAAI 知识树 + 语言树，n=2） | 生克对照/跨域验证 |

**数据源适配判据**：①能构建"领域→子领域"层级树 ②可靠时间戳（月度可采）③官方 API（合规）④与 BAAI 形态可比。

---

## 二、arXiv 评估：API 优先于 Crawl4AI

### 2.1 对比表

| 维度 | Crawl4AI 爬取 | **arXiv 官方 API** | 结论 |
|------|--------------|-------------------|------|
| 合规 | ⚠️ 需控制频率 | ✅ 官方支持（export.arxiv.org/api/query） | **API 胜** |
| 结构化 | 需 CSS/LLM 提取 | ✅ 原生 Atom XML（title/author/category/**published**） | API 胜 |
| 资源 | ⚠️ Playwright 渲染（重） | ✅ 轻量 HTTP | API 胜 |
| 分类树 | 需自行构建 | ✅ 原生分类体系（cs.AI/cs.LG/cs.CL...） | API 胜 |
| 时间序列 | 需解析日期 | ✅ **published 字段原生支持** | API 胜 |

### 2.2 关键洞察

**arXiv 分类体系（cs.* + math.* + stat.*）本身就是一棵"领域树"**——与 BAAI 知识树形态同构！按 `published` 月度统计各分类论文数 → "研究主题演化的时间序列"，直接喂五行诊断（分类=节点、论文数=节点权重、月度=快照）。

### 2.3 Crawl4AI 的重新定位

**非 arXiv 首选**（API 全覆盖），降级为**无 API 站点的 P2 补充工具**（期刊详情页、公众号、行业报告站）——进多源矩阵的 P2 层。

## 三、多源矩阵（P0/P1/P2 分级）

| 优先级 | 数据源 | 节点树 | 时间戳 | API | 与 BAAI 可比性 | 信号语义 |
|--------|--------|--------|--------|-----|---------------|---------|
| **P0** | **arXiv API** | ✅ 分类树 | ✅ 月度 | ✅ 官方 | **高** | 研究涌现（核） |
| **P0** | **BAAI 知识树**（已有） | ✅ 领域树 | ✅ 月度 | ✅ 官方 | 基准 | 机构规划（壳） |
| **P1** | **GitHub API** | ✅ 主题树 | ✅ 月度 | ✅ 官方 | **高**（技术域） | 工程实践涌现 |
| **P1** | **HuggingFace API** | ✅ 模型/数据集树 | ✅ 月度 | ✅ 官方 | **高**（AI 域） | 模型生态演化 |
| P2 | OpenAlex API | ✅ 概念树 | ✅ | ✅ 免费 | 中 | 学术图谱宏观 |
| P2 | Semantic Scholar | ✅ 引用网 | ✅ | ✅ 免费 | 中 | 引用/影响力 |
| P2 | 维基百科 API | ✅ 分类树 | ✅ 页面流 | ✅ | 低 | 概念热度 |

**P0+P1 四源即够**：BAAI（机构规划）+ arXiv（研究涌现）+ GitHub（工程实践）+ HuggingFace（AI 生态）——四个域的 O_t/E_u/C_k/K_y 时间序列 → 跨域可比性直接从 n=2 跳到 n=4。

## 四、壳-核对照价值（信号语义差异）

```
BAAI 知识树 = 机构规划的领域结构（人工构建、低频变化）→ 壳
arXiv 分布  = 研究产出的自发涌现（论文流、高频变化）   → 核
```

**BAAI 与 arXiv 恰好构成"壳-核对照"**：同一个"AI 领域"，机构怎么规划（BAAI label 树）vs 研究者实际在做什么（arXiv 论文分布）——两棵树可能有不同的五行画像（规划偏稳=土、涌现偏动=火/水）。这是壳核框架的又一应用场景：**机构之壳 vs 研究之核的对照诊断**。

## 五、四源月度管线设计（核心）

### 5.1 管线总览

```
每月快照（4 源并行）：
① BAAI：GET hub-notion.baai.ac.cn/api_v2/api/label（已有，328 节点）
         → knowledge_tree_YYYYMM.json
② arXiv：GET export.arxiv.org/api/query（分类×时间窗口，分页）
         [选 20-30 个 cs.* 子分类，按 published 月统计 → 节点树]
         → arxiv_tree_YYYYMM.json
③ GitHub：GET api.github.com（按 topic/created 月统计仓库数）
         → github_tree_YYYYMM.json
④ HuggingFace：GET huggingface.co/api/models（按 pipeline_tag/created 月统计）
         → hf_tree_YYYYMM.json

统一 schema：{nodes:[{id,name,parent,wuxing,weight}], timestamp, source}
→ 喂五行诊断引擎（七维指标）→ 输出 O_t/E_u/C_k/K_y 时间序列
```

### 5.2 统一 Schema（四源对齐）

```json
{
  "schema_version": "1.0",
  "source": "arxiv | baai | github | huggingface",
  "timestamp": "2026-08-01",
  "nodes": [
    {
      "id": "cs.AI",
      "name": "人工智能",
      "parent": "cs",
      "wuxing": "火",           // 五行标注（诊断引擎可覆盖）
      "weight": 1284            // 当月论文数/仓库数/模型数
    }
  ],
  "meta": {
    "node_count": 30,
    "total_weight": 15820,
    "api_used": "export.arxiv.org/api/query"
  }
}
```

### 5.3 各源采集细节

**① arXiv API（P0）**
```
端点：export.arxiv.org/api/query
参数：search_query=cat:cs.AI+AND+submittedDate:[202608010000 TO 202608312359]
      start=0&max_results=2000（分页）
提取：entry/title, entry/published（月），entry/category
分类树：cs.AI / cs.LG / cs.CL / cs.CV / cs.NE / cs.CR / cs.IT / math.* 等 20-30 子类
频率：月度（每月 1 日跑上月）
间隔：≥3 秒/请求（遵守 API 友好策略）
```

**② BAAI 知识树（P0，已有）**
```
端点：hub-notion.baai.ac.cn/api_v2/api/label（已验证，328 节点）
      + /reports_graph（月报列表）
快照：每月 1 日抓取 → knowledge_tree_YYYYMM.json（已实现）
```

**③ GitHub API（P1）**
```
端点：api.github.com/search/repositories
参数：q=topic:llm+created:2026-08-01..2026-08-31&per_page=100
主题树：llm / agents / computer-vision / nlp / mlops 等 20 主题
频率：月度（注意 API 速率限制：未认证 60 次/时，认证 5000 次/时——建议认证）
```

**④ HuggingFace API（P1）**
```
端点：huggingface.co/api/models
参数：pipeline_tag=text-generation&createdAt 过滤 + 分页（每页 1000）
分类树：text-generation / text-classification / image-classification 等 pipeline_tag
频率：月度
```

### 5.4 管线调度（幂等可重跑）

```
每月 1 日 02:00 触发：
  ① 四源并行采集 → 各源 raw_YYYYMM.json
  ② 统一 schema 标准化 → tree_YYYYMM.json
  ③ 数据校验（节点数/权重/时间戳完整性）
  ④ 入时间序列库 → 追加 time_series.db（月度累加）
  ⑤ 可选：喂五行诊断 → 输出月度画像

幂等性：按月快照文件命名（YYYYMM），重跑覆盖当月，不污染历史
```

## 八、风险与合规

| 风险 | 对策 |
|------|------|
| arXiv 使用条款 | 官方 API + ≥3 秒间隔 + robots.txt 遵守 + 非商业用途声明 |
| GitHub 速率限制 | 使用认证 token（5000 次/时）+ 分页控制 |
| 四源 schema 不一致 | 统一标准化层（§5.2 schema） |
| 单月数据不足（新领域冷启动） | 回填历史（arXiv 支持按年查询） |
| 时间序列未满 3 个月 | 先用 2026-06/07/08 三个月回填（BAAI 已有 06/07，arXiv/GitHub/HF 可回查） |
