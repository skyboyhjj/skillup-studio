# arXiv AI 分类五行标注仲裁确认文档

> **版本**：V1.0（2026-08-09）
> **背景**：差异 #8——参考版 `AI_CATEGORY_WUXING` 与实际版 `classify_wuxing()` 在 11 个分类中 6 个（55%）标注不一致
> **结论**：统一标注源（参考版为唯一源）+ 标注一致性校验 + 标注版本化

---

## 一、冲突清单（差异 #8）

| 分类 | 参考版 AI_CATEGORY_WUXING | 实际版 classify_wuxing() | 不一致 |
|------|--------------------------|--------------------------|--------|
| cs.AI | 火 | 水 | ⚠️ |
| cs.NE | 水 | 土 | ⚠️ |
| cs.MA | 木 | 火 | ⚠️ |
| cs.RO | 金 | 木 | ⚠️ |
| cs.IR | 金 | 火 | ⚠️ |
| cs.MM | 火 | 木 | ⚠️ |

**11 分类中 6 个（55%）不一致。**

---

## 二、问题定性：标注源分裂（不是谁对谁错）

五行是视角而非属性（已确认）——cs.AI 标火或标水均可成立，取决于标注原则。**真正的问题是同一分类在两处标注不同，导致月度时间序列断裂**：

```
同一 cs.AI：参考版算"火"、引擎算"水"
→ 上月 S_p/重心按火算，下月按水算 → 时间序列出现"虚假漂移"
→ O_t/E_u/C_k/K_y 演化全失真
```

**这是 BAAI 知识树教训的复演**："领域名规范化 bug（生成式 AI vs 生成式AI）导致 drift=1.0 伪影"——同一模式：**名称/标注不一致 → 诊断伪影**。标注源必须单一。

---

## 三、标注原则仲裁

### 3.1 参考版标注逻辑（语义映射，可解释）

| 五行 | 语义 | 分类 |
|------|------|------|
| 土 | 承载基础（方法底座） | cs.LG, stat.ML |
| 水 | 语言流动 / 神经演化 | cs.CL, cs.NE |
| 木 | 感知生发 / 多体协作 | cs.CV, cs.MA |
| 金 | 执行结构 / 筛选精确 | cs.RO, cs.IR |
| 火 | 显性活跃 / 交互 / 多模态 | cs.AI, cs.HC, cs.MM |

### 3.2 实际版问题点

| 分类 | 实际版 | 依据评估 |
|------|--------|---------|
| cs.NE=土 | 神经进化=承载？ | ⚠️ 牵强（神经=流动，参考版水更贴） |
| cs.RO=木 | 机器人=生发？ | ⚠️ 牵强（机器人=执行结构，参考版金更贴） |
| cs.MM=木 | 多媒体=生发？ | ⚠️ 牵强（多媒体=活跃，参考版火更贴） |

**6 处不一致中 3 处（NE/RO/MM）实际版缺乏清晰依据——参考版语义映射统一、可解释，仲裁胜出。**

## 四、仲裁决议（三步）

### 决议 1：统一标注源（P0，必须）

**以参考版 `AI_CATEGORY_WUXING` 为唯一标注源**：

```python
AI_CATEGORY_WUXING = {
    "cs.AI":   "火",   # 人工智能：综合、扩散、显性
    "cs.LG":   "土",   # 机器学习：基础承载（方法底座）
    "cs.CL":   "水",   # 计算语言：语言流动、理解
    "cs.CV":   "木",   # 计算机视觉：感知生发
    "cs.NE":   "水",   # 神经进化：神经流动、演化
    "cs.MA":   "木",   # 多智能体：多体协作、生发
    "cs.RO":   "金",   # 机器人：执行、结构、控制
    "cs.HC":   "火",   # 人机交互：交互活跃
    "cs.IR":   "金",   # 信息检索：筛选精确
    "cs.MM":   "火",   # 多媒体：多模态活跃
    "stat.ML": "土",   # 统计学习：统计基础
}
```

**若引擎侧不可改（已部署）**：参考脚本加"引擎标注优先"适配——但需先审核实际版标注依据（当前 3 处牵强）。

### 决议 2：标注一致性校验（P0，必须）

在采集/诊断管线加校验，任一分类不一致 → 直接报错，不产诊断：

```python
def check_wuxing_consistency(reference: dict, actual: dict) -> bool:
    """标注源一致性检查：防止标注分裂导致时间序列伪影"""
    diff = {k: (reference[k], actual.get(k)) for k in reference
            if k in actual and reference[k] != actual[k]}
    if diff:
        raise ValueError(
            f"标注源分裂 {len(diff)} 处: {diff}——必须先统一，禁止混用"
        )
    return True
```

**应用位置**：`arxiv_diagnose.py` 引擎适配层调用前 + 时间序列 build_series 前。

**原则**：宁可停，不产伪影。

### 决议 3：标注版本化（P1，建议）

标注也是"数据"——变更影响时间序列可比性：

```json
{
  "wuxing_annotation_version": "v1",
  "annotation_source": "AI_CATEGORY_WUXING",
  "annotation_rationale": "语义映射：土=承载/水=流动/木=生发/金=结构/火=活跃"
}
```

- 每次标注调整 → 版本 +1，并在时间序列文件记录
- 跨版本对比时标注"标注版本差异"——防"标注变更"被误读为"领域漂移"
- 时间序列文件 `arxiv_series.json` 增加 `annotation_versions` 字段（逐月记录）

## 六、回归验证预期（统一标注后）

统一为参考版后，模拟数据（cs.LG 权重最大）诊断预期：

```
五行分布：土主导（LG+stat.ML 权重占比最大）
主导路径：土 → 土 → 土（稳定，无虚假漂移）
S_p 量级：30-45（化/变阶段区间，视四维指标）
```

**关键验证点**：统一标注后，时间序列不再出现"同一分类跨月标不同五行"的断裂——O_t/E_u/C_k/K_y 演化反映真实领域变化，而非标注噪声。

## 七、一句话总结

> **差异 #8 确认为"标注源分裂"——55% 不一致会导致月度时间序列虚假漂移（O_t/E_u/C_k/K_y 全失真），是 BAAI"领域名 bug → drift 伪影"教训的复演。仲裁决议：①统一标注源——参考版 AI_CATEGORY_WUXING（语义映射可解释，NE/RO/MM 三条依据比实际版充分），引擎不可改则以引擎为准但需审核依据；②管线加标注一致性校验（不一致即报错、不产诊断——宁可停，不产伪影）；③标注版本化（wuxing_annotation_version v1，变更显式记录，防"标注变更"被误读为"领域漂移"）。五行是视角，但诊断必须单一视角——统一之前，宁可不诊断，不产伪影。**」
