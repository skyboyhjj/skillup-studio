## 三、P0-1 EngineAdapterV2 技术方案

### 3.1 架构（三块拼图合一）

```
四源多月树文件
   │  collect_series（复用 merge_and_calibrate 采集逻辑）
   ▼
{source: {month: nodes}}  ──► 五行标注（canonical/topic 映射）
   │
   ▼
时间演化三层构造（方案 A）：
   最早月 → 种子层（规划之始）
   中间月 → 现行层（当前状态）
   最近月 → 超越层（最新演化）
   │  weight 归一化展开（解决 v2 等权计数缺陷）
   ▼
v2 引擎 diagnose(rings)
   │
   ▼
维度映射：
   O_t = dim1_freq 主导行 pct（weight 加权）          ← 修复
   E_u = 适配层自算 1 - H_norm（weight 加权）          ← 明示 ≠ dim4
   C_k = 演化耦合度 = (sheng×1.0 + ke×0.5) / 2        ← 解决 C_k≡O_t 共线
   K_y = k_y_enhancer（火×0.4 + 土×0.3 + E_relation×0.3）← 解决 K_y=1.0
   S_p = power_mean(p=0.5, scale=100)
附加维度：dim3_edges / dim3_profile / dim4_entropy / dim5_compass（v2_extra）
```

### 3.2 三个旧问题的解法映射

| 旧问题 | fallback 病因 | v2 解法 |
|--------|--------------|---------|
| C_k ≡ O_t 共线 | fallback 中 C_k = wuxing_dist[dominant] = O_t | C_k 改为**演化耦合度**：层间主导行的生克边质量（相生=滋养演进，相克=张力转折）。时间演化模式下 dim3 边即"主导行演化路径" |
| K_y = 1.0 零区分度 | fallback 中 K_y = min(1, n_cat/11)，arXiv 11 类恒 1.0 | k_y_enhancer：K_y = w_火×0.4 + w_土×0.3 + E_relation×0.3；E_relation = β×ke_density + (1-β)×dim4.ratio（β=0.5 默认） |
| E_u 低值 | fallback 熵受分类粒度限制 | E_u 保持 1-H_norm 自算；**新增** dim5.magnitude（质心集中度）+ dim4.ratio（层间重合度）作为补充维度，报告 v2_extra |

### 3.3 关键设计决策

1. **weight 归一化展开**：v2 引擎等权计数——将节点按 weight 展开为轻量概念 `{'wuxing': X}`（arXiv 月 ~1.3 万、HF ~2.5 万，纯 Counter 毫秒级）。等价于 weight 加权统计，且让 dim3 主导行与报告口径一致
2. **时间演化语义**：种子层=最早月（规划之始）、现行层=中间月、超越层=最近月。dim3 生克边 = "主导行如何演化"——相生边=顺畅演进（种子生现行），相克边=张力转折（现行克超越）
3. **引擎纯净**：不改 v2 引擎源码，全部适配在 EngineAdapterV2 层（config 死参数 → 系数在适配层实现）
4. **schema 兼容**：输出与 merged_series.json 同构（source/month/O_t/E_u/C_k/K_y/S_p/dominant/n_nodes）+ v2_extra 附加字段

### 3.4 验收标准

- [ ] 单源多月（arXiv 06/07/08）跑通，输出 merged_series 兼容记录
- [ ] C_k ≠ O_t（共线解除：两维度取值分布不同）
- [ ] K_y 有区分度（arXiv 三月的 K_y 值不全为 1.0）
- [ ] 五行分布（weight 加权）与壳核报告口径一致（arXiv 土 26% 等）
- [ ] dim3_edges/dim3_profile 输出正确（时间演化生克边）
- [ ] fallback vs v2 对照表（同数据双引擎对比）
