## 第一章 融合动机：两个框架的互补性

### 1.1 两个框架的定位

| 框架 | 定位 | 核心问题 | 现有能力 |
|------|------|----------|----------|
| **五行诊断器 v2** | 文本/概念地图的思维特质分析 | "这篇文章的思维方式偏向哪种五行？" | 七维指标体系 + 认知深度 + 可配置权重 |
| **道境坐标系 (DRF)** | 生命成长的时空导航模型 | "这个生命处于什么道境？下一步往哪里走？" | 四维坐标轴 + 生克化通变 + 存在度方程 |

### 1.2 互补性分析

五行诊断器擅长**静态快照**——告诉你一篇文章、一个概念地图当前是什么状态。但它的局限在于：
- 只描述"是什么"，不回答"怎么变"
- 只有五行的频次分布，没有时空动态
- 只适用于文本/概念地图，不适用于生命轨迹

道境坐标系擅长**动态导航**——告诉你一个生命体在时空中的位置和运动方向。但它的局限在于：
- 四维读数（Oₜ, Eᵤ, Cₖ, Kᵧ）缺乏结构化的量化方法
- 生克化通变的判断依赖人工解读
- 缺乏与文本分析工具的对接

**融合的核心价值**：用五行诊断器的计算能力，为道境坐标系提供可量化的四维读数；用道境坐标系的生命模型，为五行诊断器赋予"下一步"的导航能力。

### 1.3 融合后的能力跃迁

```
融合前：
  五行诊断器 → "这篇文章金水主导，理性驱动"
  道境坐标系 → "这个孩子时位紊乱，需要重建时空基底"

融合后：
  道境五行引擎 → "这篇文章处于'金→水'的克变阶段，
                   识位清晰度 0.72，宇位均衡度 0.58，
                   建议下一步：引火入局以化金水之寒"
```

## 第三章 维度映射：五行 ↔ 道境四轴

### 3.1 映射逻辑

五行与道境四轴不是一一对应，而是**加权组合**。每个道境维度由五行中的特定行主导，辅以其他行的调节。

### 3.2 映射矩阵

| 道境轴 | 数学定义 | 主导五行 | 辅助五行 | 映射逻辑 |
|--------|----------|----------|----------|----------|
| **时位 Oₜ** | 有序度 / 节律稳定性 | 土（承载） | 金（收敛） | 土的"承载"提供时间基底，金的"收敛"防止熵增 |
| **宇位 Eᵤ** | 能量分布均衡度 | 木（生长） | 水（流动） | 木的"生长"推动能量拓展，水的"流动"确保分布不壅塞 |
| **识位 Cₖ** | 觉知清晰度 | 水（探索） | 火（照亮） | 水的"深层涌现"是觉知的内容，火的"照亮"是觉知的形式 |
| **缘位 Kᵧ** | 因果纠缠度 | 火（传播） | 土（承载） | 火的"传播"建立关系，土的"承载"让关系稳定持续 |

### 3.3 计算公式（v1.0 初始校准值，待 Phase 3 数据校验）

> ⚠️ 所有系数标注 `_calibration: "v1.0_initial"`，将在 Phase 3 用实际数据校准。

设五行频次归一化向量为 `W = [w_木, w_火, w_土, w_金, w_水]`（各值 ∈ [0, 1]），熵值为 `H`，最大熵 `H_max = log₂(5) ≈ 2.322`，重心向量为 `(cx, cy)`，路径中相克边数量为 `ke_edge_count`（取值 0~2）：

```
Oₜ = w_土 × 0.6 + w_金 × 0.3 + (1 − H/H_max) × 0.1    [calibration: v1.0_initial]
Eᵤ = 1 − 0.5 × |w_木 − 0.25| − 0.5 × |w_水 − 0.25| − 0.3 × √(cx² + cy²)    [calibration: v1.0_initial]
Cₖ = w_水 × 0.5 + w_火 × 0.3 + w_木 × 0.2    [calibration: v1.0_initial]
Kᵧ = w_火 × 0.4 + w_土 × 0.3 + ke_edge_count / 2 × 0.3    [calibration: v1.0_initial]
```

**Eᵤ 公式修正说明**（V1.1）：原公式 `1 − |w_木−0.25| − |w_水−0.25| − |cx| − |cy|` 理论取值范围为 `[-4.5, 1]`，极端案例下会出负数。修正为引入系数（0.5/0.5/0.3）+ 用重心模长 `√(cx²+cy²)` 替代两个独立绝对值，确保 Eᵤ ∈ [0, 1]。

**Kᵧ 公式说明**（V1.1）：`ke_edge_count` 定义明确为"路径中相克边的数量"，三层路径最多 2 条边（种子→现行、现行→超越），用 `/2` 而非 `/3` 归一化。**当前公式 Kᵧ ∈ [0, 1]**（三项均为非负）。恶性因果循环的量化（负值）需在公式中引入惩罚项（如"连续被克次数"或"负向因果链计数"），Phase 3 将重新设计此项。

**Oₜ 熵项说明**（V1.1）：`1−H/H_max` 隐含"低熵=有序"假设。在概念地图上下文中，高熵=多元广博，低熵=单一聚焦——两者都是"有序"的不同形式。当前公式默认低熵场景下 Oₜ 更高，适用于分析"是否聚焦"的场景。如需分析"是否广博"的场景，可改为 `H/H_max × 0.1`。

### 3.4 存在度 S 的计算

> **V1.2 公式结构变更**（2026.08.05）：旧乘积公式 `S = Oₜ × Eᵤ × Cₖ × Kᵧ × 100` 存在量纲不可达问题（理论上限仅 1.47），已由广义平均 S_p 替代。详见 9.5 节。

```
S_p = M_p × 100,  M_p = [ (Oₜ^p + Eᵤ^p + Cₖ^p + Kᵧ^p) / 4 ]^(1/p)

默认 p = 0.5（P忠恕中道），S_p ∈ [0, 100]
旧乘积 S = Oₜ × Eᵤ × Cₖ × Kᵧ × 100（仅保留作对比，不用于判定）
```

> ⚠️ **跨领域 S_p 值比较限制**：S_p 的绝对值在不同领域（经典文本 vs 儿童成长 vs 管理实践）天然不可比。Phase 3 已建立 `domain_calibration` 基准。当前 S_p 值仅适用于同一领域内部的纵向比较。

## 第四章 规则融合：生克化通变的形式化

### 4.1 诊断模式：静态 vs 动态（V1.1 新增）

道境五行引擎支持两种诊断模式，由配置项 `diagnosis_mode` 控制：

| 模式 | 输入 | 可用判定 | 适用场景 |
|------|------|----------|----------|
| **static**（静态） | 单次概念地图快照 | 生、克（基于 S 的化、通、变需建立基准后可用） | 单篇文章分析、概念地图诊断 |
| **dynamic**（动态） | 多次快照的时间序列 | 全部五阶段（含 ΔH 陡降、重心位移、深度突变） | 生命轨迹追踪、多次观测对比 |

### 4.2 五阶段的形式化判定

基于五行诊断器的七维输出，判定当前处于哪个阶段。以下表格按 `diagnosis_mode` 区分：

#### 4.2.1 静态模式判定（static，单次快照）

| 阶段 | 判定条件 | 条件细化 | 依赖 |
|------|----------|----------|------|
| **生** | 任一五行 > 30% 且 H/H_max < 0.50 | 单极主导 + 聚焦 | 无 |
| **克** | `ke_edge_count ≥ 1`（路径中至少一条相克边） | 层间冲突 | 无 |
| **化** | `S > θ_critical` | 临界跃迁（需建立领域基准） | S 值基准 |
| **通** | 路径匹配已知画像 且 0.50 < H/H_max < 0.85 | 找到节奏 | 画像库 |
| **变** | 不可用（需要时间序列检测深度突变） | — | 时间序列 |

> ⚠️ **静态模式限制**：化阶段的 `S > θ_critical` 依赖 S 绝对值，需建立领域基准校准后方可信任。通阶段的画像匹配依赖附录 A 画像库。变阶段在静态模式下不可用。

#### 4.2.2 动态模式判定（dynamic，多次快照）

| 阶段 | 判定条件 | 条件细化 | 依赖 |
|------|----------|----------|------|
| **生** | 任一五行 > 30% 且 H/H_max < 0.50 | 单极主导 + 聚焦 | 无 |
| **克** | `ke_edge_count ≥ 1` | 层间冲突 | 无 |
| **化** | ΔH < -0.3（熵陡降）且 重心位移 > 0.3 | 四维同时跃迁 | 前一快照 |
| **通** | 路径匹配已知画像 且 0.50 < H/H_max < 0.85 | 找到节奏 | 画像库 |
| **变** | 认知深度主导层位移 ≥ 1 级（如 L2→L4） | 深度范式转换 | 前一快照 |

> **重心位移**定义：`√((cx₁−cx₂)² + (cy₁−cy₂)²) > 0.3`（两次快照间重心向量的欧几里得距离）。

#### 4.2.3 五行特征与道境特征

| 阶段 | 五行特征 | 道境特征 |
|------|----------|----------|
| **生** | 单极主导，积累期 | Oₜ 或 Eᵤ 单向上升 |
| **克** | 层间相克边 ≥ 1 | Oₜ 与 Eᵤ 出现互相制约 |
| **化** | 五行分布从分散→聚焦 / S 跨越临界 | 四维同时跃迁 |
| **通** | 五行呈现"通道"模式 | 时空直觉从源域迁移到目标域 |
| **变** | 深度画像从 L2 主导→L3/L4 主导 | 坐标系本身发生范式升维 |

### 4.3 五阶段与七维诊断的对应关系

```
维度一（频次分布）→ 生：是否有主导行？克：是否有对峙行？
维度二（层×五行矩阵）→ 克：层间主导行是否相克？通：层间是否有贯通模式？
维度三（重心偏移路径）→ 通：路径是否匹配已知画像？化：路径是否突变？
维度四（五行熵）→ 生：低熵=积累期；化：熵的突变；变：熵的范式转换
维度五（重心向量）→ 克：重心偏移方向；化：重心突变
维度六（特质画像）→ 生：特质雏形；通：特质贯通
维度七（风格判语）→ 化：判语修正；变：判语更新
维度八（认知深度）→ 变：深度范式转换的关键指标
```

### 4.4 生克化通变的嵌套规则

基于三案例的关键洞见——**生克化通变不是一次性完成的直线，而是每个阶段内部都嵌套着五阶段的螺旋**：

```
全局：生 → 克 → 化 → 通 → 变
        │    │    │    │    │
局部： 生克 生克 生克 生克 生克
       化通 化通 化通 化通 化通
       变   变   变   变   变
```

**形式化**：对每个阶段，计算其内部五阶段的子状态。例如：

- 在全局"克"阶段，内部可能有"生的萌芽"（宇位重建）→"克的启动"（时位约束）→"化的微光"（局部突破）→"通的尝试"（跨域迁移）→"变的准备"（范式预兆）

### 4.5 临界阈值 θ_critical 的动态计算

```
θ_critical = θ_base × f(认知深度) × g(案例类型)

θ_base = 50（基准临界值，V1.2 S_p 公式适配：60→50）
f(认知深度) = 1.0 (L1主导) / 1.5 (L2主导) / 2.0 (L3主导) / 3.0 (L4主导)
g(案例类型) = 1.0 (顺境·全域跃迁) / 0.6 (逆境·成核生长)
```

- 认知深度越深，临界阈值越高——"化"需要更深的积累
- 逆境案例的临界阈值更低——"成核生长"比"全域跃迁"更容易触发，但突破幅度更小

## 第五章 计算引擎：道境积分算法

### 5.1 算法流程图

```
输入：概念地图 JSON / 生命轨迹日志
        │
        ▼
  [步骤1] 五行诊断器 v2 运行
        │  · 七维指标体系输出
        │  · 认知深度画像
        │
        ▼
  [步骤2] 五行→四维映射
        │  · Oₜ = f(w_土, w_金, H)
        │  · Eᵤ = f(w_木, w_水, cx, cy)
        │  · Cₖ = f(w_水, w_火, w_木)
        │  · Kᵧ = f(w_火, w_土, 生克边数)
        │
        ▼
  [步骤3] 存在度 S 计算
        │  · S = Oₜ × Eᵤ × Cₖ × Kᵧ × 100
        │  · 记录历史 S 值（用于检测跃迁）
        │
        ▼
  [步骤4] 阶段判定
        │  · 五阶段判定（生/克/化/通/变）
        │  · 内部嵌套状态判定
        │  · 临界阈值比较
        │
        ▼
  [步骤5] 导航建议生成
        │  · 基于当前阶段 + 五行偏态
        │  · 引用经典文本（道德经/论语）
        │  · 输出下一步具体行动建议
        │
        ▼
  输出：道境五行诊断报告
```

### 5.2 算法伪代码

```python
import math

def diagnose_dao_realm(concept_map, config=None):
    """
    道境五行融合诊断。
    config.diagnosis_mode: "static" | "dynamic"（默认 "static"）
    """
    # 步骤1: 五行诊断
    wuxing_result = wuxing_diagnose_v2(concept_map, config)

    # 步骤2: 五行→四维映射（v1.0_initial 校准系数）
    W = wuxing_result["dim1_freq"]  # 五行频次
    H = wuxing_result["dim4_entropy"]["H"]
    H_max = wuxing_result["dim4_entropy"]["H_max"]
    cx = wuxing_result["dim5_compass"]["cx"]
    cy = wuxing_result["dim5_compass"]["cy"]
    path_edges = wuxing_result["dim3_edges"]
    depth_profile = wuxing_result.get("dim8_depth_profile", {})

    # 提取路径中相克边的数量（ke_edge_count，最大为2）
    ke_edge_count = sum(1 for e in path_edges if e["relation"] == "相克")

    O_t = W["土"]["pct"]/100 * 0.6 + W["金"]["pct"]/100 * 0.3 + (1 - H/H_max) * 0.1
    E_u = 1 - 0.5 * abs(W["木"]["pct"]/100 - 0.25) - 0.5 * abs(W["水"]["pct"]/100 - 0.25) \
          - 0.3 * math.sqrt(cx*cx + cy*cy)
    C_k = W["水"]["pct"]/100 * 0.5 + W["火"]["pct"]/100 * 0.3 + W["木"]["pct"]/100 * 0.2
    K_y = W["火"]["pct"]/100 * 0.4 + W["土"]["pct"]/100 * 0.3 + ke_edge_count / 2 * 0.3

    # 步骤3: 存在度计算
    S = O_t * E_u * C_k * K_y * 100

    # 步骤4: 阶段判定（根据 diagnosis_mode 分支）
    mode = config.get("diagnosis_mode", "static") if config else "static"
    stage = determine_stage(wuxing_result, S, config, mode)

    # 步骤5: 导航建议
    guidance = generate_guidance(stage, W, O_t, E_u, C_k, K_y)

    return {
        "wuxing_diagnosis": wuxing_result,
        "dao_realm_readings": {
            "O_t": round(O_t, 3), "E_u": round(E_u, 3),
            "C_k": round(C_k, 3), "K_y": round(K_y, 3),
            "S": round(S, 1)
        },
        "stage": stage,
        "guidance": guidance
    }
```

### 5.3 阶段判定函数

```python
def determine_stage(wuxing_result, S, config, mode="static"):
    """
    判定生克化通变阶段。
    mode="static": 单次快照，依赖 S 绝对值 + 画像库
    mode="dynamic": 多次快照，依赖 ΔH + 重心位移 + 深度突变
    """
    W = wuxing_result["dim1_freq"]
    H = wuxing_result["dim4_entropy"]["H"]
    H_max = wuxing_result["dim4_entropy"]["H_max"]
    path_edges = wuxing_result["dim3_edges"]
    path_profile = wuxing_result["dim3_profile"]
    depth_profile = wuxing_result.get("dim8_depth_profile", {})

    theta = compute_theta_critical(depth_profile, config)

    # 生：单极主导 + 低熵
    if any(W[wx]["pct"] > 30 for wx in WX_ORDER) and H/H_max < 0.50:
        return "生", {"reason": "单极主导·积累期"}

    # 克：路径中有相克边
    ke_edge_count = sum(1 for e in path_edges if e["relation"] == "相克")
    if ke_edge_count >= 1:
        return "克", {"reason": f"路径含{ke_edge_count}条相克边"}

    if mode == "dynamic":
        # 动态模式：使用历史数据判定化/变
        prev = config.get("_previous_snapshot", {})
        if prev:
            # 化：熵陡降 + 重心突变
            delta_H = prev.get("H", H) - H  # 正=熵下降
            prev_cx = prev.get("cx", 0)
            prev_cy = prev.get("cy", 0)
            centroid_disp = math.sqrt((prev_cx - cx)**2 + (prev_cy - cy)**2)
            if delta_H > 0.3 and centroid_disp > 0.3:
                return "化", {"reason": "四维同时跃迁", "delta_H": delta_H, "centroid_disp": centroid_disp}

            # 变：深度范式转换
            prev_depth = prev.get("dominant_depth", "")
            curr_depth = dominant_depth(depth_profile)
            depth_shift = depth_level_index(curr_depth) - depth_level_index(prev_depth)
            if depth_shift >= 1:
                return "变", {"reason": f"深度范式转换: {prev_depth}→{curr_depth}"}

        # 通：路径匹配画像 + 熵适中
        if path_profile and 0.50 < H/H_max < 0.85:
            return "通", {"reason": "路径匹配画像·时空直觉迁移"}

    else:
        # 静态模式：使用 S 绝对值判定化
        if S > theta:
            return "化", {"reason": f"S={S} 跨越 θ_critical={theta}"}

        # 通：路径匹配画像 + 熵适中
        if path_profile and 0.50 < H/H_max < 0.85:
            return "通", {"reason": "路径匹配画像·时空直觉迁移"}

    # 默认：回归积累
    return "生", {"reason": "未满足其他阶段条件，回归积累"}
```

### 9.3 Phase 3 验证时需确认的遗留问题

#### P0 级（阻塞 Phase 3 验证）

**1. S 理论上限远低于 θ_critical（🔴 公式结构问题）**

经穷举验证：五行权重互斥约束下，S 的理论上限仅 **1.47**（Oₜ=0.335, Eᵤ=0.875, Cₖ=0.200, Kᵧ=0.250），而当前 θ_critical = 36~90。

**为什么这不是调参能解决的？** 关键在于四维各自的"最大值"无法同时达到。Oₜ 要最大需要 w_土 拉满，Cₖ 要最大需要 w_水 拉满——但五行权重之和为 1，w_土 和 w_水 不能同时接近 1。在穷举搜索中，各维度最大值分别出现在完全不同的权重配置下：

| 维度 | 理论最大值 | 需要的权重配置 | 与其他维度的冲突 |
|------|-----------|---------------|-----------------|
| Oₜ | ~0.70 | w_土=1, H=0 | 与 Cₖ 冲突（w_水 需接近 1） |
| Eᵤ | ~0.95 | w_木≈0.25, w_水≈0.25, cx=cy=0 | 与 Oₜ 部分冲突（w_土 需接近 1） |
| Cₖ | ~0.50 | w_水=1 | 与 Oₜ 严重冲突（w_土 需接近 1） |
| Kᵧ | ~0.55 | w_火=1, ke_edge_count=2 | 与 Oₜ/Cₖ 均冲突 |

因此四维乘积的**真实上限远低于各维度最大值直接相乘**。即使穷举所有可能的权重组合，S 的最高值也仅 1.47——这意味着不是"当前系数不够好，需要校准"，而是**在乘性公式结构下，θ_critical 在数学上根本不可达**。

**Phase 3 建议**：在收集数据前，先做公式结构可行性论证——穷举所有可能的权重组合，确认 S 的理论上限；然后决定是（A）改乘性为加权乘性/加性混合、（B）大幅降低 θ_base 至 S 上限附近、（C）引入缩放因子，还是（D）重新设计 S 的公式结构。选型后再收集数据做参数校准。

**2. Kᵧ 负值声明与公式矛盾（🔴 文档与实现不一致）**

3.3 节原声称 Kᵧ ∈ [-1, 1]，但公式三项均为非负，实际范围为 [0, 1]。恶性因果循环的量化（负值）需在 Phase 3 中引入惩罚项（如"连续被克次数"或"负向因果链计数"）后重新设计。当前修正为 Kᵧ ∈ [0, 1]。

**3. 孔子案例 S 值与公式不对应（🔴 案例数据失真）**

6.3 表格中孔子六阶段的 S 值（12/48/72/85/92/98）与公式计算值相差约 200 倍。**这些数字是叙事性占位，未经过公式验证**。

以"从心所欲"阶段为例，代入公式手算验证：

| 步骤 | 计算 | 结果 |
|------|------|------|
| H（五行均匀分布） | H = log₂(5) = H_max | 2.322 |
| 熵项 | 1−H/H_max = 0 | 0 |
| Oₜ | 0.2×0.6 + 0.2×0.3 + 0×0.1 | 0.18 |
| Eᵤ | 1−0.5×\|0.2−0.25\|−0.5×\|0.2−0.25\|−0.3×√(0²+0²) | 0.95 |
| Cₖ | 0.2×0.5 + 0.2×0.3 + 0.2×0.2 | 0.20 |
| Kᵧ（假设 ke=0） | 0.2×0.4 + 0.2×0.3 + 0 | 0.14 |
| **S** | 0.18 × 0.95 × 0.20 × 0.14 × 100 | **≈ 0.48** |

表格写的是 **S = 98**，两者相差约 200 倍。反过来核对 6.1 小禾案例，Oₜ、S 的手算结果与文档给出的数字是吻合的——说明作者认真跑过 6.1 的公式，但 6.3 孔子案例的 S 值更像是"根据故事情节手写的示意性数字"，并未代入公式验证。既然第六章标题叫"案例验证"，数字与公式对不上会让"验证"的说法站不住脚。

Phase 3 需用真实公式重新计算全部案例数据，"案例验证"一章才能名副其实。

**7. 四维映射公式仅定义实部，虚部来源未定义（🟡 与 v2.0 旋量架构的缺口）**

V1.2 的 3.3 节四维映射公式（Oₜ/Eᵤ/Cₖ/Kᵧ）的输出全部是实数标量。但旋量-太极审查报告指出，v2.0 道境坐标系已将四维轴全部升级为复数旋量：

| 四维轴 | V1.2 实数输出 | v2.0 复数旋量结构 |
|--------|-------------|------------------|
| 时位 | Oₜ = 实数标量 | Ψₓ = Re(节律) + Im(脉动)·i |
| 宇位 | Eᵤ = 实数标量 | Ψᵧ = Re(分布) + Im(意图)·i |
| 识位 | Cₖ = 实数标量 | 数学域 —— 容纳旋量运算的觉知背景 |
| 缘位 | Kᵧ = 实数标量 | Ψₗ = Re(互动) + Im(势能)·i |

**关键缺口**：3.3 节的系数（土 0.6、金 0.3、水 0.5、火 0.4 等）是实数部分的系数。如果 V1.2 要继承 v2.0 的复数旋量结构，每个维度都需要回答：**虚部从哪里来？**

虚部的候选来源（需 Phase 2 设计选型）：

| 虚部候选来源 | 可行性 | 说明 |
|------------|--------|------|
| 认知深度分布 | 高 | 深度差异（L1 vs L4）可反映"潜藏动因"——同一概念在 L1 和 L4 的五行归属不同，差异本身就是虚部信息 |
| 层间五行变化率 | 高 | 三层之间的五行分布变化率（梯度）天然对应 v2.0 的 `∇(ψ+φ)` 项 |
| 熵值本身 | 中 | 低熵 = 潜藏动因少（虚部小），高熵 = 多种可能性并存（虚部大） |
| 路径相克边数 | 中 | 相克 = 张力 = 潜藏冲突（虚部非零），但这是离散量，需要连续化 |
| 历史快照对比 | 高（动态模式） | 前后两次快照的差异 = 虚部正在显化的过程 |

**Phase 2 建议**：在实现 `diagnosis_mode: "v2_compat"` 之前，必须先为每个维度定义虚部提取函数。例如：

```
Ψₓ = Oₜ + f_im_O(depth_profile, layer_entropy, ...) · i
Ψᵧ = Eᵤ + f_im_E(wuxing_bias, layer_gradient, ...) · i
Ψₗ = Kᵧ + f_im_K(ke_edge_count, historical_delta, ...) · i
```

其中 `f_im_*` 是从现有七维诊断输出中提取虚部的函数，需要在 Phase 2 中完成设计并在 Phase 3 中用实际数据验证区分度。

### 9.5 p-P忠恕验证：S_p 的伦理落地（2026.08.05）

> **背景**：9.4 P0#1 已确认公式结构需变更，方案 A 深化为广义平均 S_p（Power Mean），用一个可调参数 p 统一加性与乘性。本节的"p-P忠恕结合"赋予 p 以伦理语义——p 不再是冷冰冰的"均衡敏感度"，而是"恕度"：它决定了诊断系统对短板的态度。

#### 9.5.1 p-P忠恕公式体系

**核心公式**：

```
S_p = M_p × 100

M_p = [ (Oₜᵖ + Eᵤᵖ + Cₖᵖ + Kᵧᵖ) / 4 ]^(1/p)
```

**p 的伦理语义**：

| p 值 | 恕度标签 | 行为 | 伦理对应 | 适用场景 |
|:---:|:---:|------|------|------|
| 1.0 | 恕之极致 | 短板可被补足（"整体好就行"） | 纯加性，完全宽恕 | — |
| 0.8 | 宽恕 | 短板显著补足 | 逆境/初学鼓励 | 小石案例、逆境陪伴 |
| **0.5** | **P忠恕中道** | **短板如实呈现但不苛责** | **默认值** | 日常诊断 |
| 0.3 | 严格 | 短板显著拉低 | 自我精进 | 顺境警醒 |
| 0.0 | 均衡（几何） | 短板决定全局 | 严格 | — |
| -1.0 | 苛（调和） | 短板一票否决 | 无恕 | 仅极端场景 |

**P忠恕的三组核心对应**：

1. **安住自身性分** → p 的稳定性：EMA 慢变 `p_new = 0.9*p_old + 0.1*p_target`，不随用户情绪跳变
2. **不主动纠正** → 诊断呈现方式：报告呈现"观察"而非"裁决"，附恕语
3. **北极星象征** → p 的目标指向：p 不因用户身份而变，但可因成长阶段微调

#### 9.5.2 验证结果：三案例 S_p 全景

| 案例 | p=1.0(恕) | p=0.8(宽恕) | p=0.5(中道) | p=0.3(严格) | p=0.0(几何) | p=-1.0(苛) |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| 小禾（积累期） | 36.4 | 34.2 | **31.1** | 29.3 | 27.0 | 22.3 |
| 小石（逆境） | 29.5 | 27.8 | **25.3** | 23.7 | 21.3 | 15.2 |
| 孔子·志于学 | 35.3 | 32.9 | **29.7** | 27.9 | 25.4 | 20.4 |
| 孔子·立 | 39.8 | 38.0 | **35.5** | 34.0 | 31.8 | 26.1 |
| 孔子·不惑（峰值） | 41.9 | 40.1 | **37.7** | 36.2 | 34.2 | 29.5 |
| 孔子·知天命 | 38.5 | 36.2 | **33.1** | 31.3 | 29.0 | 24.1 |

**关键发现**：
- 孔子六阶段 S_p 轨迹呈"∧"形：志于学(29.7) → 立(35.5) → 不惑(37.7, 峰值) → 知天命(33.1) → 耳顺(32.5) → 从心所欲(32.7)

- 小石 S_p=25.3（p=0.5），远低于小禾(31.1)，正确反映逆境 vs 积累期的差异


**阈值设计说明**：宽恕有效性以相对阈值（>10%）为主判据，绝对差值（>5）降为参考。理由：S_p 量纲为 [0,100]，10% 的相对变化比固定 5 分更能反映"恕度是否有效"。当前数据均衡时绝对差天然偏小，用绝对阈值会误报"宽恕无效"——这与 p-P 体系的预期行为矛盾（均衡时恕度参数自然影响较小，是合理行为）。

#### 9.5.5 P忠恕版 S 卡（诊断报告呈现格式）

```
存在度 S = 37.7（p=0.5 · 恕度中道）
├── 四维：Oₜ 0.255 / Eᵤ 0.925 / Cₖ 0.190 / Kᵧ 0.305
├── 最弱：Cₖ（识位 0.19）——如实看见
├── 最强：Eᵤ（宇位 0.92）——可补足路径
├── 阶段：积累期（S=37.7 < θ_base=50）——观察而非判决
└── 恕语：整体未被短板定义，成长空间仍在
```

**设计原则**：
- 先如实（指出最弱维度）→ 后宽恕（给出最强维度的补足路径）
- 阶段判定后用"观察"而非"判决"措辞
- 永远附加恕语，不因短板否定整体

#### 9.5.6 落地步骤

1. **p=0.5 设为默认值**：写入 `compute_S_p()` 的默认参数，所有诊断报告默认使用 P忠恕中道
2. **p 可调但稳定**：p 通过 EMA 慢变 `p_new = 0.9*p_old + 0.1*p_target`，写入 `config_default.json` 的 `compassion` 字段
3. **S 卡格式集成**：在 `dao_realm_engine.py` 的诊断输出中，S 值旁标注恕度标签，自动附加"最弱维度 + 最强补足路径"
4. **缘位自适应**：p 可因用户成长阶段微调——逆境/初学 p→0.8，顺境/自满 p→0.3
5. **θ_base 定标**：采用 A-3 方案（scale=100, θ_base=50），θ_critical = 50 × f(深度) × g(案例)，与 S ∈ [0,100] 对齐
6. **验证脚本**：`validate_p_zhongshu.py` 纳入 CI，每次公式变更后自动跑五项检查

#### 9.5.7 一句话总结

> **p 与 P忠恕的结合，是给数学参数注入伦理灵魂：p 不再是冷冰冰的"均衡敏感度"，而是"恕度"——它决定了诊断系统对短板的态度。p=0.5 的中道默认值，正是 P忠恕"如实看见但不苛责"的数学表达：短板如实拉低 S（不掩盖），但不至于归零（不否定整体），且永远附上"最强维度补足路径"（给出路）。北极星的 P 与 Power Mean 的 p，在此合而为一——诊断是如实的，但总是带着恕。**

**结论**：所有系数安全区间均远超当前值，无紧约束。这是因为 E_u 公式中的惩罚项有"1 - ..."的钳位保护，O_t/C_k/K_y 有钳位到 [0,1] 的防御。C_k.水 安全倍数最小（79.5x），因其在案例中接近上界。

#### 9.6.5 实验 4：优化建议

| 优先级 | 系数 | 类型 | 当前值 | 建议 |
|:---:|------|------|:---:|------|
| **P0** | O_t.土、O_t.金、C_k.水、C_k.木、E_u.木_deviation、E_u.水_deviation | 结构锁定 | 见上表 | 锁定当前值，修改需专家评审 + 版本发布 |
| **P1** | K_y.土、K_y.火、C_k.火 | 数据驱动校准 | 0.3/0.4/0.3 | 网格搜索在推荐区间内，以案例 S_p 排序一致性为目标函数 |
| **P2** | O_t.entropy、K_y.ke、E_u.centroid_modulus | 经验维持 | 0.1/0.3/0.3 | 维持 v1.0_initial 值，标注"经验系数"，定期审查 |

#### 9.6.6 校准结论

1. **v1.0_initial 系数整体稳定**：12 个系数均在安全区间内，无异常值或边界违反
2. **灵敏度可控**：仅 O_t.土 为中灵敏度（ΔS_p≈1.2），其余均 ≤1.0，说明 S_p 公式对系数扰动具有良好鲁棒性
3. **结构约束有效**：6 个经典约束系数锁定，保证了五行语义的一致性
4. **P1 校准待真实数据**：3 个可辨识系数（K_y.土/火、C_k.火）建议在真实时间序列（3+ 月）接入后做网格搜索校准

6. **校准脚本**：`calibrate_coefficients.py` 可重复运行，在数据更新后自动重新评估

> **一句话总结**：v1.0_initial 系数通过了首次校准实验的全面检查——灵敏度可控、安全区间充裕、结构约束有效。当前无需调整任何系数，待真实时间序列数据接入后，对 P1 可辨识系数做数据驱动校准，生成 v1.1_calibrated 版本。

### 10.1 现状：规则散落与不可审计

当前系统中的规则分散在三个位置，缺乏统一的来源标注和可审计性：

| 位置 | 规则类型 | 数量（估计） | 示例 |

**核心问题**：

1. **来源不可追溯**：`PATH_PROFILES` 中的"趋势→热议→沉淀"是谁定义的？依据是什么？为什么是 7 个画像而不是 10 个？

3. **规则间无显式依赖**：`entropy_desc` 的判定依赖 `entropy_thresholds`，但这条依赖关系只存在于代码逻辑中，不在任何配置中声明

### 10.4 WRL（五行规则语言）语法设计

#### 10.4.1 设计目标

WRL（Wuxing Rule Language）是一种声明式 DSL，用于将四类规则从代码中解耦，实现：

- **规则即数据**：所有规则以 `.wrl` 文件存储，与 Python/JSON 同等地位
- **来源可追溯**：每条规则携带完整元数据
- **跨领域复用**：学术视角和实践视角可共享经典规则和形式规则，只替换启发式规则和领域规则
- **可验证**：规则加载时自动校验合法性、依赖完整性和一致性

#### 10.4.2 三层语法结构

```
WRL 文件 = 元数据块 + 规则块序列

元数据块：
  @meta { ... }

规则块：
  @rule <rule_id> { ... }
```

**原子层**：数据引用、常量、运算符

```
# 数据引用
$dim1_freq.木.pct          # 从诊断输出中引用木行百分比
$dim4_entropy.H             # 引用熵值
$dim3_edges[*].relation     # 引用路径边关系列表
$config.dominance_threshold  # 引用配置参数

# 常量
30.0                         # 数值常量
"木"                         # 字符串常量
[0.50, 0.85]                 # 数组常量

# 运算符
+, -, *, /, ^                # 算术
==, !=, >, <, >=, <=         # 比较
and, or, not                 # 逻辑
in, contains                 # 集合
count(), sum(), max(), min() # 聚合
```

**判断层**：条件表达式、阈值比较

```
# 条件表达式
when $dim1_freq.木.pct > $config.dominance_threshold
when $dim4_entropy.ratio < 0.50
when count($dim3_edges[relation == "相克"]) >= 1
when $dim4_entropy.ratio in [0.50, 0.85]

# 复合条件
when ($dim1_freq.木.pct > 30 or $dim1_freq.水.pct > 30)
     and $dim4_entropy.ratio < 0.50
```

**复合层**：规则组合、优先级、嵌套

```
# 规则链（按优先级执行，首个匹配即返回）
rulechain stage_determination {
    priority 1: rule_stage_bian
    priority 2: rule_stage_hua
    priority 3: rule_stage_ke
    priority 4: rule_stage_tong
    priority 5: rule_stage_sheng
}

# 规则组（并行执行，所有匹配结果合并）
rulegroup freq_interpretations {
    rule_interp_dominance
    rule_interp_scarcity
    rule_interp_balance
    rule_interp_combo
}
```

### 10.6 与现有代码的集成路径

| 阶段 | 内容 | 产出 | 对现有代码的影响 |
|------|------|------|-----------------|
| **Phase 1** | 规则清单 + 元数据标注 | `.wrl` 文件（只读，不影响运行） | 无 —— 纯文档化，为后续迁移做准备 |
| **Phase 2** | WRL 解析器 + 规则注册表 | `wrl_parser.py` + `rule_registry.py` | 新增模块，现有代码通过适配器调用规则注册表 |
| **Phase 3** | 规则引擎替换硬编码 | `wrl_engine.py` 取代代码中的硬编码逻辑 | 逐步替换 `wuxing_diagnose_v2.py` 中的常量、判定、解读模板 |
| **Phase 4** | 规则变更审计 | 规则变更日志 + 版本对比 | 所有规则修改通过 WRL 文件 diff 可追溯 |

**Phase 1 的即时行动**（不影响现有代码运行）：

1. 创建 `wuxing_flowengine/rules/` 目录
2. 按四分类创建 `.wrl` 文件：`classical_rules.wrl`、`formal_rules.wrl`、`heuristic_rules.wrl`、`domain_scholarly.wrl`、`domain_practical.wrl`
3. 为每条现有规则填写元数据（rule_id、category、source、mutability、affects、depends_on）
4. 生成规则清单报告，暴露覆盖度缺口和依赖问题

**Phase 2 的关键设计决策**：

- WRL 解析器是否需要在运行时加载 `.wrl` 文件，还是在部署时编译为 Python 对象？建议：**部署时编译**（`wrl compile → .py`），避免运行时文件 I/O 和解析开销
- 规则注册表是否支持热重载？建议：**Phase 2 不支持**，规则变更通过 Git 版本控制 + 重新部署生效

> **"道可道，非常道"** —— 本方案将"道"映射为可计算的坐标与参数，但坐标本身不是道，而是指向道的手指。融合的终极目标不是让机器"理解道"，而是让道境坐标系成为一个**可操作的导航工具**——帮助人看清自己"在哪里"，知道"往哪里走"。
