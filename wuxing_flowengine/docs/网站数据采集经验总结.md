> 项目：五行诊断与道境坐标系 · 数据采集层
> 日期：2026-07-31

## 一、总览：采集了什么

| 数据层 | 数据源 | 采集方式 | 产出 |
|--------|--------|----------|------|
| 静态结构 | 知识树 SVG 图谱 (323 节点, 791 边) | 浏览器 JS 提取 + 导出 JSON | `2026-07-30_snapshot.json` |

## 二、数据源架构分析

### 2.1 智源社区的数据分层

```
hub.baai.ac.cn
├── 前端层 (Nuxt SSR)
│   ├── 知识树图谱页: /knowledge-tree/graph
│   │   └── 渲染为 SVG，节点/边数据在 JS 运行时中
│   └── 知识树详情页: /knowledge-tree/{docId}
│       └── 含"科研月报"Tab，月度报告列表
│
├── API 层 (hub-notion.baai.ac.cn)
│   ├── GET /api_v2/api/reports_graph
│   │   └── 返回所有领域最新月报摘要（id, title, docId, createdAt）
│   └── GET /api_v2/api/reports_detail?title={领域名}&id={reportId}
│       └── 返回单份月报的完整 Tiptap JSON 文档
│
└── 缓存层 (hub-cache.baai.ac.cn)
    └── 静态资源（封面图等）
```

### 2.2 关键教训：前端 SSR + API 的两层架构

智源社区采用 **Nuxt SSR 渲染 + 独立 API 服务** 架构。这意味着：

- **API 可直接调用**：`reports_graph` 和 `reports_detail` 端点无需认证，纯 HTTP GET 即可获取 JSON
- **API 跨域友好**：`hub-notion.baai.ac.cn` 独立于前端域名，CORS 策略宽松
- **但 API 不暴露所有信息**：论文列表嵌入在 Tiptap JSON 的 `ordered_list` / `bullet_list` 块中，需要解析

**经验**：优先探测 API 层，API 能做的不要用浏览器。API 的响应是结构化 JSON，解析成本远低于 DOM 爬取。

## 三、API 采集的五个关键教训

### 3.1 教训一：API 响应格式 ≠ 你期望的格式

**问题**：`reports_detail` 返回的是 Tiptap 编辑器的富文本 JSON，不是结构化的论文列表。论文标题嵌入在 `ordered_list` 或 `bullet_list` 的嵌套结构中。

**Tiptap JSON 结构示例**：
```json
{
  "type": "doc",
  "content": [
    { "type": "heading", "attrs": { "level": 2 }, "content": [{"text": "代表性论文"}] },
    { "type": "ordered_list", "content": [
      { "type": "listItem", "content": [
        { "type": "paragraph", "content": [{"text": "Paper Title Here"}] }
      ]}
    ]}
  ]
}
```

**正确做法**：递归遍历 `content` 树，收集所有 `ordered_list` 和 `bullet_list` 的 `listItem` 文本。不要假设论文在固定位置。

**脚本模板**：
```python
def find_ordered_lists(blocks, depth=0):
    """递归查找所有有序/无序列表"""
    papers = []
    for b in blocks:
        if b.get('type') in ('ordered_list', 'bullet_list'):
            for item in b.get('content', []):
                for p in item.get('content', []):
                    text = ''.join(ct.get('text','') for ct in p.get('content', []))
                    if text.strip():
                        papers.append(text.strip())
        if 'content' in b and isinstance(b['content'], list):
            papers.extend(find_ordered_lists(b['content'], depth+1))
    return papers
```

### 3.2 教训二：同一 API 的不同领域可能返回不同格式

这是本次采集中最隐蔽的陷阱。

**现象**：`reports_detail` 对 13 个领域返回的"代表性论文"区块，有 12 个领域存储的是英文论文标题，但 **软件工程与编程的 5 月报** 存储的是中文摘要。

**影响**：
- 基于英文关键词的五行分类器对中文摘要完全失效
- 初始分析中软件工程与编程的月际漂移虚高至 1.1042（实际仅为 0.2688）
- 五行分布结论被错误翻转（火行 +3.0% vs 实际 -1.9%）

**根因**：科研月报由科研智能体 AREX 自动生成，不同领域/月份的生成模板可能不一致。软件工程与编程的 5 月报可能在生成时使用了不同的模板。

**正确做法**：
1. 采集后立即检查每个领域的数据格式（语言、长度、结构）
2. 对异常数据单独处理——通过 `reports_detail` API 的嵌套 `ordered_list` 结构重新提取
3. 在流水线中增加格式验证步骤：检测非英文标题并报警

### 3.3 教训三：API 返回的论文数量不等于实际可用数量

| 领域 | API 返回 | 实际可用 | 原因 |
|------|---------|---------|------|
| 大语言模型 (5月) | 30 | 15 | 论文分散在多个列表块中 |
| 自然语言处理 | 0 | 0 | 该领域无月报数据 |
| 知识表示与逻辑推理 | 0 | 0 | 同上 |

**经验**：API 返回的条目数不可盲信，必须逐项验证内容是否为有效论文标题。

### 3.4 教训四：API URL 参数编码

`reports_detail` 的 URL 参数包含中文领域名，必须正确 URL 编码：

```python
import urllib.parse

url = 'https://hub-notion.baai.ac.cn/api_v2/api/reports_detail?title=%s&id=%s' % (
    urllib.parse.quote('软件工程与编程'),  # 必须编码
    '866c61cc-6b89-4e5d-81cf-0e9de13865a3'
)
```

**经验**：中文参数务必使用 `urllib.parse.quote()` 编码，否则 API 可能返回空或错误。

### 3.5 教训五：API 的历史数据回溯限制

**问题**：`reports_graph` API 只返回最新一期月报，不提供历史月份的分页或筛选参数。

**解决方案**：通过知识树详情页的月报 Tab 获取历史报告 ID。每个领域详情页有两个月报链接（05月、06月），点击后 URL 中的 `report_id` 参数即为历史报告的 ID。

**关键发现**：通过浏览器访问知识树详情页，确认了系统仅有两个月报（05月、06月），无 4 月及更早数据。**科研月报系统从 2026 年 5 月开始运营**。

## 四、浏览器采集的两个关键教训

### 4.1 教训六：弹窗拦截是浏览器自动化的第一道坎

**问题**：访问 `hub.baai.ac.cn` 首页时，"知识树🌲上线啦"弹窗会拦截点击事件，导致 `browser_click` 失败。

**解决方案**：
```javascript
// 在点击前移除弹窗
document.querySelector('.hub-dialog__wrapper')?.remove();
document.querySelector('.el-dialog__wrapper')?.remove();
```

**经验**：浏览器自动化脚本的第一行应该总是处理弹窗/模态框/cookie 横幅。

### 4.2 教训七：SVG 节点提取的坐标信息

知识树 SVG 图谱中每个节点的 `<g>` 元素包含 `transform` 属性，编码了节点的 (x, y) 坐标。提取这些坐标对于后续的可视化和空间分析至关重要。

**经验**：SVG 数据提取不仅需要节点名称，坐标信息同样重要——它反映了知识树的空间组织逻辑。

## 五、数据验证的五个检查点

每次采集完成后，必须执行以下验证：

| 检查点 | 方法 | 阈值 |
|--------|------|------|
| 1. 语言检测 | 检查每条标题是否包含英文字母 | 英文占比 < 80% → 标记异常 |
| 2. 数量一致性 | 对比 API 返回条数与实际有效条数 | 差异 > 0 → 人工检查 |
| 3. 领域覆盖 | 检查是否所有目标领域都有数据 | 缺失 → 记录并跳过 |
| 4. 重复检测 | 同一领域内标题去重 | 重复率 > 5% → 检查来源 |
| 5. 格式一致性 | 同领域不同月份格式是否一致 | 不一致 → 单独处理 |

**本次实战验证结果**：
- 软件工程与编程 5 月：语言检测失败（中文摘要），触发重新采集
- 大语言模型 5 月：数量不一致（API 返回 30 条，实际有效 15 条）
- 自然语言处理、知识表示与逻辑推理：领域覆盖缺失，确认无月报

## 六、采集工具链选择

| 工具 | 适用场景 | 不适用场景 |
|------|----------|------------|
| `urllib.request` + JSON | 直接 API 调用，结构化数据 | 需要 JS 渲染的页面 |
| 浏览器自动化 | 需要交互（点击、翻页）、SSR 页面 | 简单 API 调用（开销大） |
| `browser_evaluate` | 提取页面 DOM 数据 | 跨域 API 请求 |
| Python 脚本 | 数据处理、格式转换、验证 | 实时交互 |

**决策树**：
```
需要采集数据
├── 有公开 API？
│   ├── 是 → 用 urllib/requests 直接调 API
│   │   └── 数据格式异常？ → 浏览器辅助验证
│   └── 否 → 浏览器自动化
│       ├── 静态页面？ → browser_navigate + browser_evaluate
│       └── 需要交互？ → browser_click + browser_wait_for
└── 需要历史数据？
    ├── API 支持分页/筛选 → 直接用 API
    └── API 不支持 → 浏览器模拟用户操作获取
```

## 七、可复用的采集模板

### 7.1 API 采集模板

```python
import json, urllib.request, urllib.parse

def fetch_report_detail(domain: str, report_id: str) -> dict:
    """通用月报详情采集"""
    url = 'https://hub-notion.baai.ac.cn/api_v2/api/reports_detail?title=%s&id=%s' % (
        urllib.parse.quote(domain), report_id
    )
    req = urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0'})
    with urllib.request.urlopen(req, timeout=30) as resp:
        return json.loads(resp.read().decode())

def extract_papers_from_tiptap(content: list) -> list[str]:
    """从 Tiptap JSON 中提取论文标题"""
    papers = []
    def walk(blocks):
        for b in blocks:
            if b.get('type') in ('ordered_list', 'bullet_list'):
                for item in b.get('content', []):
                    for p in item.get('content', []):
                        text = ''.join(ct.get('text','') for ct in p.get('content', []))
                        if text.strip():
                            papers.append(text.strip())
            if 'content' in b and isinstance(b['content'], list):
                walk(b['content'])
    walk(content)
    return papers

def validate_papers(papers: list[str]) -> dict:
    """验证论文标题质量"""
    total = len(papers)
    english = sum(1 for t in papers if any(c.isascii() and c.isalpha() for c in t[:20]))
    return {
        'total': total,
        'english_titles': english,
        'english_ratio': english / total if total else 0,
        'needs_review': english / total < 0.8 if total else True
    }
```

### 7.2 浏览器采集模板

```javascript
// 在知识树详情页提取月报列表
const reports = [];
document.querySelectorAll('a').forEach(link => {
```

## 九、核心原则总结

1. **API 优先，浏览器兜底**：能调 API 就不开浏览器；API 返回的数据是结构化 JSON，解析成本远低于 DOM 爬取

2. **先探结构，再写代码**：调用 API 后先用 `print(json.dumps(data, indent=2)[:2000])` 看结构，不要假设格式

3. **逐领域验证，不信任模板**：同一 API 对不同领域可能返回不同格式的内容，必须逐领域检查

4. **语言检测是必须的**：基于关键词的分类器/分析器对语言敏感，采集后必须验证数据语言

5. **时间范围不可假设**：API 返回的是"最新"而非"全部"，历史数据需要单独确认可回溯范围

6. **弹窗是第一道坎**：浏览器自动化脚本的第一行应该处理弹窗/模态框

7. **数据验证放在采集流水线中**：采集 → 验证 → 修正（如需）→ 存储，验证不是可选的
